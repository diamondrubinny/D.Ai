# D.Ai Evolve: מערכת שמפתחת ומתקנת את עצמה לפי הצרכים של המשתמש (תוכנית + v0.1)

> מערכות הפעלה מתעדכנות לפי מה שהיצרן החליט. ב־D.Ai OS המחשב **מזהה מה חסר למשתמש**, מציע לבנות את זה, **בונה, בודק ומתקן בעצמו**, ומשלב את התוצאה במערכת: אפליקציה, יכולת מערכת או אוטומציה. הכל מקומי: בלי ענן, בלי טלמטריה, ושום דבר לא משתנה בלי אישור.

## 1. הלולאה

```
   ┌──────────── מזהה צורך (Evolve, מקומי) ◄──────────────┐
   │  בקשה שלא נענתה · פקודה שחוזרת · קובץ שאין לו תוכנה │
   │  · ממצא של Doctor · משאלה שנכשלה                    │
   ▼                                                       │
 מציע (Command / התראה שבועית / dai-evolve)                │
   │  "שמתי לב ש… רוצה ש…?"   (המשתמש מאשר)              │
   ▼                                                       │
 בונה (Forge):  מתכון · אפליקציה · אוטומציה                 │
   │                                                       │
   ▼                                                       │
 בודק ומתקן (Workshop): מריץ בארגז חול → שגיאה? → ה־AI     │
   │  מתקן לפי ה־traceback → בודק שוב (עד 2 תיקונים)       │
   ▼                                                       │
 משלב: תפריט התחל · טיימר · תוכנית Tune עם undo ───────────┘
```

## 2. רכיבים

| רכיב | מה הוא עושה | שלב |
|------|-------------|-----|
| **Workshop** (‏`dai_forge.workshop`) | כל אפליקציה שה־AI כותב **מורצת בארגז חול לפני שהמשתמש רואה אותה** (בלי רשת, בלי תצוגה אמיתית, ‏`DAI_SELF_TEST=1`). קריסה → ה־traceback חוזר ל־AI עם בקשה לתקן, עד 2 תיקונים. המשתמש רואה "נבדק ✓" או "לא עבר בדיקה" ומה השגיאה | v0.1 |
| **אוטומציות** (Forge, סוג `automation`) | ‏"+ כל יום ב־18:00 תמחק מההורדות קבצים בני יותר מ־30 יום". ה־AI כותב סקריפט, **הלוח זמנים מפוענח בכללים** (לא ע"י AI), והסקריפט רץ ב־systemd timer של המשתמש, **בארגז חול** עם הרשאות מוצהרות. הודעה למשתמש: הסקריפט מדפיס `NOTIFY: טקסט`, וה־runner (מחוץ לארגז) מציג התראה | v0.1 |
| **Evolve** (‏`dai-evolve`) | מנוע שמזהה צרכים מאותות מקומיים (§3) ומציע פעולה מוכנה. ההצעות מופיעות ב־D.Ai Command (שורה ריקה), ב־`dai-evolve`, ובהתראה שבועית אם יש חדשות | v0.1 |
| **משאלות** | בקשה שלא נענתה נשמרת ברשימת משאלות מקומית. כשמשהו משתנה (מותקן מודל, נוסף מתכון), Evolve מציע לנסות שוב | v0.1 |
| **D.Ai Heal** (‏`dai-heal`): תיקון עצמי בצ'אט | כשמשהו **קורס או נכשל** (אפליקציה, שירות, אפליקציה שנבנתה ב־Forge, רכיב של D.Ai), מופיעה התראה: "‏X קרסה. לפתוח עזרה?". לחיצה פותחת **חלון צ'אט**: המערכת מסבירה בשפה פשוטה מה קרה, מציעה תיקון מוכן, ומחילה אותו **רק אחרי אישור**, ואז בודקת שהבעיה נעלמה. אפשר גם לפתוח את הצ'אט בעצמך: ‏"משהו לא עובד", ‏`Super+F1`, או `dai-heal` (§4) | v0.1 |
| שיתוף מתכונים ואפליקציות בין משתמשים | ייצוא/ייבוא חתום, קטלוג קהילתי | בהמשך |
| בקשת פיצ'ר ל־D.Ai | "המערכת לא יודעת X" → טיוטת issue ב־GitHub, רק בלחיצה של המשתמש ובלי מידע אישי | בהמשך |

## 3. אותות (כולם מקומיים, ונמחקים אחרי 30 יום)

| אות | מקור | הצעה לדוגמה |
|-----|------|-------------|
| בקשה שלא נענתה | ‏D.Ai Command: חיפוש בלי תוצאות (`~/.local/state/dai/wishes.jsonl`, בלי שאילתות שמתחילות ברווח, כמו בהיסטוריה) | ‏"חיפשת 3 פעמים 'ספר דיגיטלי'. לבנות/להתקין?" → ‏`+ <הבקשה>` |
| פקודה שחוזרת | היסטוריית D.Ai Command: אותה פקודת `>`/`$` 3 פעמים ומעלה | ‏"את `df -h` הרצת 5 פעמים. ליצור אוטומציה יומית שמתריעה כשהדיסק מתמלא?" |
| קובץ שאין לו תוכנה | ‏`~/Downloads`, ‏`~/Documents`, ‏`~/Desktop` (30 יום): סיומת שאין לה יישום ברירת מחדל (`xdg-mime`) | ‏"יש לך 4 קבצי EPUB ואין תוכנה שפותחת אותם" → מתכון `ebook-reader` |
| ממצא של Doctor | ‏`dai-doctor` (מהיר: דיסק, סוללה) | ‏"הדיסק כמעט מלא" → ‏`!פנה מקום בדיסק` |
| משאלה שנכשלה | ‏Forge: בקשה שלא הובנה, או AI שלא היה זמין | ‏"ביקשת X כשלא היה מודל. עכשיו יש. לנסות שוב?" |

- **פרטיות:** האותות נקראים מקבצים שכבר קיימים אצל המשתמש (היסטוריה, תיקיות), ונשמרים ב־`~/.local/state/dai` עם הרשאות 0600. שום דבר לא נשלח. ‏`dai-evolve off` מכבה הכל ומוחק את המשאלות.
- **בלי AI:** זיהוי האותות מבוסס כללים, ולכן מהיר ועובד גם בלי מודל. ה־AI נכנס לפעולה רק כשהמשתמש מאשר הצעה לבנייה.
- הצעה שנדחתה ("לא, תודה") לא חוזרת.

## 4. D.Ai Heal: תקלה → צ'אט → תיקון

```
 קריסה / שירות נכשל / שגיאה        "משהו לא עובד" / Super+F1
 (systemd-coredump, systemctl       │
  --failed, יומן D.Ai, Forge apps)  │
        │  dai-heal watch (מקומי, קריאה בלבד)
        ▼                           ▼
   התראה: "Firefox קרסה. לפתוח עזרה?" ──► חלון צ'אט (dai-heal)
                                          1. מה קרה (עובדות: מה קרס, מתי, כמה פעמים, השגיאה)
                                          2. אבחנה: כללים קבועים, ואם יש מודל, גם ה־AI המקומי מסביר
                                          3. תיקון מוצע ככפתור: [תקן] [לא עכשיו]
                                          4. אחרי תיקון: בדיקה שהבעיה נעלמה, ו־undo
```

| מה קרה | מקור העובדה | תיקון מוצע (כולם עם אישור, כולם עם undo כשאפשר) |
|--------|-------------|-------------------------------------------------|
| אפליקציה שנבנתה ב־Forge קרסה | ה־runner שומר את ה־traceback (בתוך ה־sandbox, בלי מידע מחוץ לו) | ה־Workshop: ה־AI מתקן לפי השגיאה, בודק בארגז חול, ושומר גרסה חדשה (‏undo לגרסה הקודמת) |
| תוכנה רגילה קרסה (core dump) | ‏`coredumpctl` (שם התוכנה וחבילה, בלי תוכן הזיכרון) | הפעלה מחדש · איפוס הגדרות התוכנה (עם גיבוי, אפשר להחזיר) · התקנה מחדש של החבילה (Tune) |
| שירות מערכת נכשל | ‏`systemctl --failed` | הפעלה מחדש של השירות (Tune) · הצגת שורות היומן הרלוונטיות |
| רכיב של D.Ai נכשל | יומן D.Ai | הצעה לדווח ב־GitHub (טיוטה, בלי מידע אישי, רק בלחיצה) |
| "הצליל / הרשת / המדפסת לא עובדים" | ‏D.Ai Doctor | התיקונים של Doctor (Tune / Forge) |

- **שום תיקון לא קורה מעצמו.** הצ'אט מציע; המשתמש מאשר; שינויי מערכת עוברים דרך Tune (סיסמת מנהל, יומן, undo).
- ‏**ה־AI מסביר, הכללים מתקנים:** התיקונים הם פעולות מוגדרות מראש (Tune, Forge, הפעלה מחדש). ה־AI המקומי לא מריץ פקודות שהוא המציא.
- ‏**פרטיות:** תוכן core dumps לא נקרא ולא נשלח. נשמרים רק שם התוכנה, הזמן והשגיאה, מקומית, ‏30 יום.
- ‏**לא להציף:** התראה אחת לכל תוכנה ל־10 דקות, ו־"אל תשאל שוב על X".

## 5. אבטחה

| איום | בקרה |
|------|------|
| קוד AI מזיק רץ בזמן הבדיקה | הבדיקה רצה **באותו ארגז חול** (bubblewrap): בלי רשת, בלי הבית, בלי תצוגה, ‏`--cap-drop ALL`, עד 8 שניות. בלי bubblewrap **אין בדיקה**, ואף פעם אין הרצה מחוץ לארגז |
| לולאת תיקונים אינסופית או "תיקון" שמסיר בדיקות | לכל היותר 2 תיקונים. הקוד הסופי עובר את אותה ולידציה (AST, גודל) ומוצג למשתמש |
| אוטומציה עושה משהו לא צפוי ברקע | ארגז חול, הרשאות מאושרות מראש (`downloads`, ‏`documents`, ‏`network`), יומן ריצות, ‏`dai-forge auto list/pause/remove`. הלוח זמנים מפוענח בכללים, עם מרווח מינימלי של 15 דקות |
| אוטומציה כ־root | **אין.** אוטומציות רצות כמשתמש בלבד. שינויי מערכת עוברים רק דרך Tune, עם סיסמה |
| הצעה מטעה (prompt injection דרך שם קובץ) | הצעות נבנות מתבניות קבועות. שמות קבצים לא נכנסים לפרומפט של ה־AI, רק סוג הקובץ |
| איסוף מידע על המשתמש | אותות מקומיים בלבד, 30 יום, 0600, כיבוי במשפט |
| Heal "מתקן" בלי רשות, או ה־AI מריץ פקודה מזיקה | תיקונים רק מרשימה סגורה (Tune/Forge/הפעלה מחדש), תמיד עם אישור. ה־AI מנסח הסבר בלבד |
| הודעת שגיאה זדונית (prompt injection בטקסט השגיאה) | טקסט השגיאה מוצג למשתמש ונכנס ל־AI רק כ"נתונים". הוא לא יכול להוסיף תיקונים לרשימה |

## 6. בדיקות

- יחידה: זיהוי סוג הבקשה (אוטומציה, לוח זמנים בעברית ובאנגלית), לולאת בדיקה ותיקון עם AI מזויף וקוד שקורס, יצירת timer ו־service, ‏NOTIFY, כל אות של Evolve, דחיית הצעה, כיבוי.
- ‏Heal: קריסה של אפליקציית Forge ← traceback ← תיקון ב־Workshop; שירות שנכשל ← הצעת הפעלה מחדש; התראה מוגבלת בקצב; ‏VM: שירות משתמש שנכשל בכוונה מופיע בצ'אט עם התיקון.
- ‏VM: קוד שקורס נבדק ב־bubblewrap אמיתי ומדווח; אוטומציה נוצרת כ־timer אמיתי של systemd ורצה; ‏`dai-evolve suggest` מוצא קובץ EPUB בלי תוכנה ופקודה שחוזרת.
