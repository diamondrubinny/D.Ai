# D.Ai Forge — המערכת שהמשתמש מרחיב בעצמו (v0.1)

> "‎+ תתקין אנטי וירוס", "‎+ תוסיף סנכרון קבצים בין המחשבים שלי", "‎+ תבנה לי אפליקציה של טיימר פומודורו".
> מנהל המחשב כותב בשורת הפקודות שבשורת המשימות, וה־AI המקומי מקים, משלב ובונה. אין צורך לחכות לעדכון של D.Ai: היכולות החדשות הן **מתכונים** ו**אפליקציות** שנשמרים אצל המשתמש, והמשתמש מנהל ומעדכן אותם בעצמו.

## 1. מה זה

D.Ai Forge מטפל בשלושה סוגי בקשות. כולן מגיעות מאותה שורה: `+` בשורת הפקודות שליד "התחל", או בחלון D.Ai Command.

| בקשה | דוגמה | מה קורה |
|------|-------|---------|
| **יכולת / אינטגרציה** (מתכון) | `+ תתקין אנטי וירוס` · `+ add syncthing` | נמצא מתכון מוכן, והוא הופך לתוכנית D.Ai Tune: חבילות, שירותים, פורטים ותזמון. התוכנית מוצגת, המנהל מאשר אותה בסיסמה, ואפשר לבטל אותה (undo) |
| **מתכון חדש מה־AI** | `+ תכין את המחשב לשרת הדפסה לרשת הבית` | כשאין מתכון מוכן, ה־AI המקומי מחבר מתכון **רק מפעולות הקטלוג**. המתכון מסומן "נכתב ע"י AI", מאושר ידנית, ואפשר לשמור אותו לשימוש חוזר ולשיתוף |
| **בניית אפליקציה** | `+ תבנה אפליקציה של רשימת קניות` | ה־AI המקומי כותב אפליקציה (Python/Qt, דף Web או כלי טרמינל). היא נשמרת ב־`~/Apps/<שם>`, מופיעה בתפריט "התחל", ורצה ב**ארגז חול** עם הרשאות מוצהרות |

אפשר גם לשפר אפליקציה קיימת: `+ שנה את shopping: הוסף כפתור מחיקה`. כל שינוי שומר גרסה קודמת, ו־`dai-forge app undo shopping` מחזיר אחורה.

## 2. "בלי צורך בעדכונים": המשתמש הוא הבעלים

- **מתכונים הם נתונים, לא קוד.** קובץ JSON קצר שמונה צעדים מהקטלוג הסגור של D.Ai Tune. מתכון חדש לא דורש גרסה חדשה של המערכת.
- שלוש ספריות: מובנים ב־`/usr/share/dai/forge/recipes`, של המנהל ב־`/etc/dai/forge/recipes`, ושל המשתמש ב־`~/.local/share/dai/forge/recipes`.
- **קדימות בטוחה:** מתכון של המנהל גובר על מתכון מובנה. מתכון אישי **לא** יכול להחליף מתכון קיים באותו שם, כדי שתוכנה זדונית שרצה כמשתמש לא תוכל "להחליף" את מתכון האנטי וירוס. מקור המתכון תמיד מוצג.
- `dai-forge recipe export/import`: שיתוף מתכונים בין מחשבים. ייבוא עובר את אותה ולידציה.
- האפליקציות שבנה המשתמש שלו לחלוטין: קוד פתוח בתיקייה שלו, עם גרסאות, ובלי תלות בשרת.
- עדכוני האבטחה של Debian נשארים דלוקים כברירת מחדל, וזו החלטה של המשתמש: `dai-tune "כבה עדכונים אוטומטיים"` מכבה אותם, עם סימון "מחליש אבטחה".

## 3. ארכיטקטורה

```
"+ טקסט"  (שורת הפקודות בשורת המשימות / D.Ai Command / dai-forge CLI)
     │
 intent.py ── כללים: מתכון? אפליקציה? הסרה? ──(לא ברור)──► AI מקומי (JSON schema)
     │
     ├── מתכון ──► recipes.py ──► Requests ──► dai_tune.planner (ולידציה מלאה)
     │                                              │
     │                       תוכנית ← אישור ← pkexec dai-tune-helper (root, ולידציה מחדש)
     │                                              │  journal + undo (אותו מנגנון של Tune)
     │
     └── אפליקציה ──► ai.py (קוד ב־JSON schema) ──► apps.py
                         בדיקה סטטית (AST) · גרסאות · manifest הרשאות · קובץ .desktop
                                              │
                                   dai-forge run <app>  ──►  bubblewrap (ארגז חול)
```

ל־Forge **אין** מנגנון הרשאות root משלו. כל שינוי מערכת עובר דרך `dai-tune-helper` הקיים, שמאמת מחדש כל צעד מול הקטלוג.

## 4. פעולות קטלוג חדשות (ב־D.Ai Tune)

| מזהה | פרמטרים | scope | הגבלות |
|------|---------|-------|--------|
| `service.unit` | `unit`, `enabled` | מערכת | שם `*.service`/`*.timer` לפי regex. היחידה חייבת להיות מותקנת. רשימה שחורה: nftables, apparmor, systemd-*, sddm, dbus, polkit, NetworkManager, ssh (יש לו פעולה ייעודית) |
| `service.user_unit` | `unit`, `enabled` | משתמש | יחידה מ־`/usr/lib/systemd/user` בלבד |
| `flatpak.remote` | `name` | מערכת | רק `flathub`, וכתובתו קבועה בקוד |
| `flatpak.install` / `flatpak.remove` | `apps` | מערכת | מזהה reverse-DNS, עד 5 אפליקציות, מ־flathub בלבד |
| `antivirus.schedule` | `enabled`, `frequency` (daily/weekly) | מערכת | יוצר `dai-av-scan.timer`/`.service` בתוכן קבוע ומוקשח. סריקת `/home` עם ClamAV, ובידוד קבצים נגועים ל־`/var/lib/dai/quarantine` (0700) |

## 5. מתכונים מובנים (v0.1)

| מזהה | מה מקים | צעדים |
|------|---------|-------|
| `antivirus` | ClamAV: עדכון חתימות אוטומטי וסריקה יומית עם הסגר | packages ← service freshclam ← antivirus.schedule |
| `flathub` | חנות אפליקציות Flathub | flatpak.remote |
| `syncthing` | סנכרון קבצים מוצפן בין מחשבים, ברשת המקומית בלבד | package ← user unit ← פורטים 22000/tcp+udp, 21027/udp לרשת מקומית |
| `containers` | Podman, קונטיינרים בלי root | packages |
| `wireguard` | VPN מסוג WireGuard (דרך NetworkManager) | packages |
| `nextcloud` | לקוח סנכרון Nextcloud | packages |
| `vscode` | Visual Studio Code מ־Flathub | flatpak.remote ← flatpak.install |
| `telegram`, `signal` | מסרים מ־Flathub | flatpak.remote ← flatpak.install |

פורמט מתכון:

```json
{
  "format": 1,
  "id": "antivirus",
  "name": {"en": "Antivirus (ClamAV)", "he": "אנטי וירוס (ClamAV)"},
  "description": {"en": "...", "he": "..."},
  "match": {"en": ["antivirus", "virus scanner"], "he": ["אנטי וירוס", "סורק וירוסים"]},
  "steps": [{"action": "packages.install", "params": {"names": ["clamav", "clamav-freshclam"]}}]
}
```

"הסר אנטי וירוס" בונה תוכנית הפוכה: הסרת החבילות שהמתכון התקין, כיבוי השירותים, וסגירת הפורטים שנפתחו.

## 6. אפליקציות: ארגז חול והרשאות

כל אפליקציה שנבנתה מקבלת `dai-app.json`:

```json
{"format": 1, "name": "shopping", "title": "רשימת קניות", "kind": "gui",
 "entry": "app.py", "permissions": {"network": false, "documents": false}, "version": 2}
```

`dai-forge run <app>` מריץ אותה ב־**bubblewrap** (אותו מנגנון של Flatpak):

| משאב | ברירת מחדל |
|------|-----------|
| קבצי המערכת (`/usr`, `/etc`) | קריאה בלבד |
| קוד האפליקציה | קריאה בלבד (`/app`) |
| בית (HOME) | תיקיית נתונים פרטית של האפליקציה בלבד (`~/.local/share/dai/apps/<app>`) |
| שאר הבית, מפתחות SSH, דפדפן | **לא נראים** |
| רשת | **חסומה** (`--unshare-net`), אלא אם אושרה ההרשאה `network` |
| מסמכים | רק בהרשאה `documents`, ורק `~/Documents` |
| תצוגה | רק ה־socket של Wayland. אין X11, ואין גישה לחלונות אחרים |
| הרשאות קרנל | `--cap-drop ALL`, `--new-session` (מונע הזרקת הקשות לטרמינל), `--die-with-parent` |

- **הרשאות נאשרות בהתקנה,** כמו בטלפון: "האפליקציה מבקשת גישה לרשת. לאשר?". שינוי הרשאה דורש אישור מחדש.
- **אפליקציות Web** (`index.html`) נפתחות בדפדפן. אם `network=false`, D.Ai מזריק Content-Security-Policy עם `connect-src 'none'`. מדיניות CSP נוספת של האפליקציה רק מחמירה, ולא יכולה לבטל את שלנו.
- **בדיקה סטטית (AST)** לפני שמירה: מסמנת subprocess, `eval`/`exec`, ctypes, מחיקת עצים ושימוש ברשת. הבדיקה מיועדת **לשקיפות** ומוצגת למשתמש. גבול האבטחה הוא ארגז החול.
- קוד שלא עובר `ast.parse` לא נשמר. מגבלת גודל: 64KB.

## 7. מי יכול

- **מתכונים עם שינויי מערכת:** רק משתמש מנהל (קבוצת `sudo`). Forge בודק את זה מראש, כדי לחסוך תוכנית שתיכשל. האכיפה האמיתית היא polkit (`auth_admin_keep`) בתוך ה־helper.
- **בניית אפליקציות:** כברירת מחדל רק מנהלים, כפי שהתבקש. `/etc/dai/forge.json` → `{"apps_for_all_users": true}` פותח את זה לכולם. האפליקציות תמיד ברמת משתמש ובארגז חול.

## 8. Threat model מקוצר

| איום | בקרה |
|------|------|
| ה־AI "ממציא" צעד מסוכן במתכון | JSON schema מגביל לפעולות הקטלוג. ה־planner וה־helper מאמתים כל צעד. כל פרשנות AI דורשת אישור ידני (‎`--yes` נדחה) |
| מתכון זדוני מוחדר לתיקיית המשתמש | לא יכול לדרוס מתכון מובנה או של המנהל. המקור מוצג. כל צעד מערכת דורש סיסמת מנהל |
| אפליקציה שה־AI כתב מכילה קוד מזיק (בטעות או ב־prompt injection) | ארגז חול: בלי רשת, בלי גישה לבית או למפתחות, וקבצי מערכת לקריאה בלבד. בדיקה סטטית מוצגת לפני הרצה |
| דליפת מידע מהאפליקציה לאינטרנט | רשת חסומה כברירת מחדל. ב־Web: CSP |
| פתיחת שירות לרשת דרך מתכון | פורטים לרשת המקומית בלבד, ומסומן "מחליש אבטחה" + הקלדת "כן" |
| הסרת רכיבי מערכת דרך מתכון הפוך | רשימת החבילות המוגנות של Tune חלה גם כאן |
| AI בענן | אין. הכל רץ מקומית (daid, AF_UNIX בלבד) |

## 9. ממשקים

- **חלון D.Ai Forge** (`dai-forge-gui`, ‏Super+B, או "D.Ai Forge" בתפריט התחל): שדה בקשה, רעיונות ומתכונים מוכנים בלחיצה, ו"האפליקציות שלי". מתכון מוצג ככרטיסי צעדים עם סיכון והשפעה על האבטחה. פעולה מחלישה דורשת להקליד "כן", ומתכון של AI דורש לסמן "בדקתי את כל הצעדים". ההקמה עוברת דרך polkit (חלון סיסמה), ובסוף יש כפתור ביטול. בבניית אפליקציה הקוד מופיע בזמן שה־AI כותב אותו, ואחר כך מוצגות הרשאות לאישור וכפתורים להפעלה, פתיחת הקוד, שינוי וחזרה לגרסה קודמת. אם אין מודל, החלון מציע להוריד את מודל הקוד (עם אימות SHA-256).
- **שורת הפקודות בשורת המשימות / D.Ai Command:** `+` ואחריו בקשה. מוצגת תצוגה מקדימה (מתכון והצעדים שלו, או "בניית אפליקציה ב־AI"). Enter פותח את חלון D.Ai Forge עם הבקשה.
- `dai-forge "<בקשה>"` · `dai-forge list` · `dai-forge undo`
- `dai-forge recipe list|show|export|import|remove`
- `dai-forge app list|run|show|undo|permissions|remove|add <name> <file>` (קוד שהמשתמש כתב בעצמו)
- `--dry-run`, `--yes` (לא חל על AI ולא על פעולות מחלישות)

## 10. מגבלות ידועות (v0.1)

- איכות הקוד תלויה במודל המקומי. מומלץ `dai-models install qwen2.5-coder-1.5b`, ו־Forge בוחר אותו אוטומטית לבניית קוד. מודל 0.5B מתאים רק לאפליקציות פשוטות מאוד.
- אפליקציות בארגז חול עדיין לא חשופות לקורא מסך (AT-SPI), כי חשיפת אפיק הנגישות מאפשרת לקרוא תוכן של אפליקציות אחרות. יש לבחון את זה מול יועץ נגישות ואבטחה לפני שנפתח את זה. דורש אימות מול התיעוד הרשמי של AT-SPI.
- סריקה בזמן אמת (on-access, ‏`clamonacc`) עוד לא מופעלת, ובינתיים יש סריקה מתוזמנת. on-access דורש fanotify ובדיקת ביצועים.
- אפליקציות Web רצות בארגז החול של הדפדפן, ולא ב־bubblewrap.
