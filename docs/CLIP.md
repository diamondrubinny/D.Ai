# D.Ai Clip: היסטוריית לוח שלא שומרת סיסמאות (v0.1)

> ‏Windows (‏Win+V) ו־macOS (מ־2025) נותנים היסטוריית העתקות, אבל ב־Windows היא נשמרת גם עם סיסמאות שהועתקו ממנהל סיסמאות, ויכולה להסתנכרן לענן. ב־LXQt אין היסטוריה בכלל ([RESEARCH.md](RESEARCH.md)). ב־D.Ai OS לוחצים **Super+V**, רואים את מה שהעתקתם לאחרונה, ובוחרים. **סיסמאות, מפתחות ומספרי כרטיס לא נכנסים להיסטוריה**, וההיסטוריה נשמרת רק בזיכרון ונמחקת ביציאה.

## 1. מה רואים

| פעולה | מה קורה |
|-------|---------|
| ‏**Super+V** | חלון קטן עם 30 ההעתקות האחרונות (החדשה למעלה), ושדה חיפוש |
| הקלדה | מסננת את הרשימה |
| ‏Enter / לחיצה | מעתיקה שוב ומדביקה בחלון הקודם (Ctrl+V) |
| ‏Shift+Enter | רק מעתיקה, בלי להדביק (למשל לטרמינל, שבו מדביקים ב־Ctrl+Shift+V) |
| ‏Delete | מוחקת את הפריט מההיסטוריה |
| "ניקוי הכל" / ‏Esc | מוחקת הכל / סוגרת |
| ‏D.Ai Command | ‏"היסטוריית העתקות", ‏"clipboard history" |
| טרמינל | `dai-clip list`, ‏`dai-clip clear`, ‏`dai-clip pause 10`, ‏`dai-clip off` / `on` |

## 2. מה **לא** נשמר

| מקרה | איך מזוהה | מה קורה |
|------|-----------|---------|
| העתקה ממנהל סיסמאות (KeePassXC ועוד) | סוג התוכן `x-kde-passwordManagerHint` בין הסוגים שמוצעים (`wl-paste --list-types`), או `CLIPBOARD_STATE=sensitive` | לא נשמר. מנהל הסיסמאות מנקה את הלוח בעצמו |
| מפתח פרטי (`-----BEGIN … PRIVATE KEY-----`), ‏JWT, ומפתחות API מוכרים (`sk-`, ‏`ghp_`, ‏`github_pat_`, ‏`glpat-`, ‏`xox?-`, ‏`AKIA…`, ‏`AIza…`) | תבנית | לא נשמר, **והלוח מתנקה אחרי 90 שניות** אם הוא עדיין מכיל את אותו דבר |
| השמה של סיסמה או מפתח בטקסט (`password=…`, ‏`api_key: …`, ‏`סיסמה: …`) | תבנית | לא נשמר, והלוח מתנקה אחרי 90 שניות |
| מספר כרטיס אשראי (13–19 ספרות שעוברות בדיקת Luhn) | בדיקת ספרת ביקורת | כמו למעלה |
| מספר תעודת זהות ישראלי (9 ספרות עם ספרת ביקורת תקינה) | בדיקת ספרת ביקורת | כמו למעלה |
| קוד אימות חד־פעמי (4–8 ספרות בלבד) | תבנית | לא נשמר (ולא מתנקה) |
| "נראה כמו סיסמה": מילה אחת, 8–64 תווים, בלי רווחים, עם לפחות 3 מתוך אותיות קטנות/גדולות/ספרות/סימנים, ולא כתובת, נתיב או מייל | היוריסטיקה | לא נשמר (ולא מתנקה, כי זה ניחוש) |
| תמונות וקבצים | לא טקסט | לא נשמר (v0.1: טקסט בלבד) |
| טקסט גדול מ־100KB | גודל | לא נשמר |
| ‏`dai-clip pause` / ‏`off` | קובץ סימון | לא נשמר כלום עד הזמן שנקבע / עד `on` |

> טעות לכיוון הזה (משהו לא־סודי שלא נשמר) מקובלת. טעות לכיוון השני (סיסמה שנשמרה) היא מה שאנחנו מונעים.
> מה שלא נשמר עדיין אפשר להדביק כרגיל: ההיסטוריה לא נוגעת בלוח עצמו, חוץ מהניקוי אחרי 90 שניות.

## 3. איך זה בנוי

```
labwc (data-control) ──► wl-paste --watch dai-clip _store   (autostart, per user)
                                  │  stdin = התוכן, CLIPBOARD_STATE = data|nil|clear|sensitive
                                  ▼
                       dai_clip.secrets.classify()  ──► secret? → לא נשמר (+ ניקוי אחרי 90ש')
                                  ▼
          $XDG_RUNTIME_DIR/dai-clip/history.json   (tmpfs = זיכרון בלבד, 0700/0600, נעילה)
                                  ▲
Super+V ──► dai-clip (PyQt6) ──► wl-copy (התוכן ב־stdin, לא ב־argv) ──► wtype Ctrl+V
```

- ‏**זיכרון בלבד:** ‏`$XDG_RUNTIME_DIR` הוא tmpfs של המשתמש (‏`/run/user/<uid>`, הרשאות 0700). הוא לא נכתב לדיסק, ו־systemd-logind מוחק אותו ביציאה. אם אין `XDG_RUNTIME_DIR`, ‏dai-clip לא שומר כלום (אין fallback לדיסק).
- 30 פריטים לכל היותר, וכל פריט נמחק אחרי 12 שעות. העתקה חוזרת של אותו טקסט מעלה אותו למעלה.
- הכתיבה אטומית (קובץ זמני + `os.replace`) עם `flock`, כי כל העתקה מריצה תהליך `_store` נפרד.
- ‏**נבדק בקוד המקור:** ה־man page של wl-clipboard 2.2.1 (הגרסה ב־Debian 13) מתאר `CLIPBOARD_STATE=sensitive`, אבל הקוד של 2.2.1 מגדיר רק `data` ו־`nil`. רק הגרסה הבאה מזהה את הסימון. לכן dai-clip בודק בעצמו את רשימת הסוגים, ותומך גם במשתנה לגרסאות הבאות.
- ‏`wl-paste --watch` דורש את פרוטוקול data-control של wlroots, ש־labwc תומך בו (נבדק במכונה הווירטואלית ב־CI).
- התוכן עובר ל־`wl-copy` דרך stdin, כי argv של תהליך גלוי לכל המשתמשים ב־`ps`.

## 4. אבטחה ופרטיות

| איום | בקרה |
|------|------|
| סיסמה נשמרת בהיסטוריה | סימון מנהל הסיסמאות, תבניות, ספרות ביקורת, היוריסטיקה (§2) |
| ההיסטוריה נשארת על הדיסק / בגיבוי | ‏tmpfs בלבד; ‏D.Ai Backup לא מגבה את `/run` |
| משתמש אחר קורא את ההיסטוריה | תיקייה 0700 וקובץ 0600, בתוך `/run/user/<uid>` שהוא 0700 |
| קובץ היסטוריה זדוני/פגום | קריאה עם מגבלת גודל (4MB), ‏JSON בלבד, בדיקת טיפוסים; קובץ פגום מתאפס |
| symlink attack בתיקייה | ‏`O_NOFOLLOW`, בדיקה שהתיקייה שייכת למשתמש ואינה symlink |
| ‏AI / רשת | אין. ‏dai-clip לא שולח כלום ולא משתמש ב־AI |

## 5. מגבלות (v0.1)

- טקסט בלבד (בלי תמונות וקבצים).
- ההדבקה האוטומטית משתמשת ב־Ctrl+V. בטרמינל משתמשים ב־Shift+Enter ואז Ctrl+Shift+V.
- אפליקציות X11 (דרך XWayland) מסונכרנות ללוח של Wayland על ידי labwc, ולכן נכנסות גם הן.
- ההיוריסטיקה של "נראה כמו סיסמה" היא ניחוש. היא עלולה לפספס סיסמה פשוטה (למשל `password123`) ולדלג על טקסט שאינו סודי.
- לא נבדק עדיין מול רכיב הנגישות של קורא המסך Orca מעבר לשמות נגישים בסיסיים (דורש בדיקה ידנית).

## 6. בדיקות

- יחידה: `classify()` לכל סוג סוד ולטקסט רגיל (כולל עברית, כתובות, נתיבים, קוד), אחסון (מגבלות, כפילויות, תפוגה, הרשאות, קובץ פגום, symlink), ‏CLI ‏(`_store` עם כל ערך של `CLIPBOARD_STATE`, ‏pause/off), ‏GUI (סינון, מחיקה, Enter/Shift+Enter עם copier מוזרק), ‏D.Ai Command.
- ‏VM ‏(CI): ‏`wl-copy` אמיתי בסשן labwc → הטקסט מופיע ב־`dai-clip list`; העתקה עם `--type` של מנהל סיסמאות לא מופיעה; ‏`sk-…` לא מופיע.
