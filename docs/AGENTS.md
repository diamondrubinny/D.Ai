# D.Ai Agents: סוכנים שמבצעים פעולות (שלב 1)

> נכתב ב־2026-10-31 אחרי "תוסיף מערכת סוכני AI שמבצעים פעולות שונות". סוכן ב־D.Ai הוא Diamond עם **ארגז כלים סגור**:
> הוא מתכנן צעד־צעד, כל צעד הוא כלי מוכר עם ארגומנטים שנבדקים, כל צעד שמשנה משהו עובר דרך D.Ai Tune (תוכנית,
> אישור, ביטול), והכול נרשם. אין shell, אין קוד חופשי, אין פעולה בלי האדם.

## 1. הרעיון

"סוכן: תזכיר לי מחר ב־8 לשלם את החשבון ותרשום שהשרברב מגיע ביום שלישי", "agent: find the lease from last month and
read it to me", "agent: what is weak in my security and fix the easy parts". ‏Diamond מפרק את המטרה לצעדים
(כלי + ארגומנטים + למה), מריץ כלי קריאה מיד, ומבקש אישור לפני כל כלי שעושה משהו. בסוף: תשובה בשפה של האדם.

## 2. הארכיטקטורה (apps/dai-agent)

| רכיב | מה |
|---|---|
| `tools.py` | הקטלוג: `Tool(name, risk, describe, schema, run)`. ‏`risk="read"` רץ בלי שאלה; `risk="act"` רק אחרי אישור |
| `agent.py` | הלולאה: הנחיית מערכת עם רשימת הכלים → JSON אחד לצעד (`{"thought","tool","args","final"}`; הסכמה היא `anyOf` עם ענף לכל כלי: `tool` קבוע (`const`) ו־`args` עם השמות, הטיפוסים והגבולות של הכלי הזה בלבד, כך שהדקדוק של llama-server לא מאפשר כלי מחוץ לתפקיד או ארגומנט מומצא) → הרצה → התוצאה חוזרת כהודעה → עד `done` או 8 צעדים. ‏`--script FILE` מריץ צעדים נתונים בלי מודל |
| `roles.py` | תפקידים = תת־קבוצת כלים + הנחיה: `secretary`, `organizer`, `guard`, `tutor`, `all` |
| `journal.py` | כל ריצה ב־`~/.local/share/dai/agents/<id>.json` (0600): מטרה, תפקיד, צעדים, אישורים, תוצאות, תשובה. `dai-agent history` |
| `cli.py` | `dai-agent run "goal" [--role R] [--yes] [--dry-run] [--script FILE]`, `tools`, `roles`, `history` |

| כלי | סיכון | מה |
|---|---|---|
| `facts(question)` | קריאה | מה Diamond יודע על D.Ai (docs/AI.md §6) |

## 3. אבטחה ופרטיות

- **ארגז כלים סגור:** שם כלי לא מוכר → הצעד נדחה; ארגומנטים נבדקים לפי סוג ואורך; טקסט הוא תמיד ארגומנט, לעולם לא shell.
- **כל שינוי דרך Tune:** `do` הולך לאותה `execute_plan` של `dai-tune` (תוכנית מודפסת, אישור, יומן, `dai-tune undo`). ‏`--yes`
  מאשר רק צעדי משתמש ניטרליים/מחזקים; החלשה או מערכת → שאלה תמיד (כמו `--yes` ב־Tune עצמו).
- **המודל לא רואה סודות:** הכלים מחזירים טקסט קצר (שמות קבצים, כותרות ממצאים), לא תוכן קבצים ולא מפתחות.
- **מקומי:** המשימה `general` של Diamond; עם ספק חיצוני שנבחר ל־general, המטרה והתוצאות (שמות קבצים!) יוצאות אליו,
  והחלון/CLI אומרים זאת (`dai-ai where`). מדיניות ארגונית שאוסרת ספקים חלה.
- **גבולות:** 8 צעדים, 120 שניות לכלי, תשובה עד 2,000 תווים; לולאה שחוזרת על אותו צעד נעצרת.
- **יומן:** ריצות ב־0600; `dai-agent history` מראה; מחיקה = מחיקת הקובץ.

## 4. מגבלות כנות

המודל המקומי הקטן (Qwen2.5 0.5B) מתכנן לא תמיד נכון; הסכמה מבטיחה צעד תקין (כלי של התפקיד, ארגומנטים שלו), לא תוכנית
חכמה: בריצה 41249628203 הוא שאל `facts` במקום `posture`, ואז חזר על אותו צעד ונעצר (קוד 1). ‏`--script` ובדיקות היחידה
בודקים את המנגנון בלי המודל; ב־VM הריצה עם המודל מתקבלת ב־0, 1 (נעצר) או 3 (לא תכנן), כל עוד הצעד הראשון הוא כלי של
התפקיד, והמנגנון, היומן והסירוב לכלי לא מוכר עובדים. מודל גדול יותר (1.5B+) או ספק חיצוני משפרים מאוד.

## 5. בדיקות

יחידה: הכלים עם Tune מזויף (plan/do/remind/note), אישור (callback) ו־`--yes` שנדחה להחלשה, סכמת הצעד, כלי לא מוכר,
עצירה אחרי 8 צעדים ואחרי חזרה, יומן, roles, ‏CLI עם צ'אט מזויף ו־`--script`. ‏VM: `agent: tools, a script and the model`
(‏`dai-agent tools/roles`, ריצת `--script` שיוצרת פתק ותזכורת, ריצה עם המודל שמסתיימת ב־0 או 3, יומן קיים).

## 6. שלב 2: חלון הסוכן (נבנה 2026-11-01)

> אותו סוכן, אותם כללים, בלי טרמינל: הצעדים כרשימה, אישור בכפתור שמראה את תוכנית Tune לפני שמשהו משתנה, ‏Raz
> מבקר את החלון בבדיקות היחידה. "סוכן: …" ב־D.Ai Command פותח את החלון במקום טרמינל.

| רכיב | מה |
|---|---|
| `gui.py` | `AgentWindow`: שורת מטרה + תפקיד + "רק להראות" (הרצת ניסיון) + התחלה; רשימת צעדים (→ קריאה, ⚠ פעולה, ✗ נדחה, ✓ הוחל) עם התוצאה בגופן קבוע; כרטיס אישור; התשובה; העתקה / הקראה (D.Ai Speak) / סגירה |
| הלולאה | `run_agent` רץ ב־QThread. ‏`approve(step)` בחוט העבודה מחשב את תוכנית Tune של הצעד (`plan_from_text` + `describe`), שולח אותה לחלון ומחכה ל־Event; הכפתור "לאשר" או "לדלג" משחרר אותו. סגירת החלון = דילוג |
| ביצוע | אחרי אישור בחלון שהראה את התוכנית, `apply_plan` של Tune (היומן, הביטול, העוזר דרך polkit לצעדי מערכת). אין `input()` ואין `--yes`: האישור הוא הכפתור, וגם תוכנית שמחלישה אבטחה מסומנת באדום **ובמילים** ("מחלישה אבטחה") לפניו |
| פרטיות | שורה קבועה: "במחשב הזה" או "המטרה ותוצאות הכלים נשלחות ל־<ספק>" (`dai-ai where`); היומן כמו ב־CLI |
| כניסות | `dai-agent window ["goal"] [--role R]`, ‏`dai-agent.desktop` (תפריט: Utility), ‏Command: "agent: …" / "סוכן: …" → החלון עם המטרה; "agent:" ריק → חלון ריק |

בדיקות: יחידה (Raz `assert_accessible` בעברית ובאנגלית עם כרטיס אישור פתוח ותשובה; אישור בכפתור → `apply_plan`; דילוג →
לא בוצע; תוכנית שמחלישה מסומנת; סגירה בזמן המתנה משחררת את החוט; הרצת ניסיון לא מבצעת), ‏Command (הפעולה פותחת את
החלון), ‏VM (`dai-agent.desktop` קיים, `dai-agent window --version`).

## 6ג. שלב 4: סוכן שמדבר, סוכן בטלפון, מדיניות ארגונית (נבנה 2026-11-01)

> שלושה דברים קטנים שסוגרים את המעגל: אומרים לסוכן מה לעשות והוא עונה בקול; אותו חלון עובד בטלפון במצב מגע;
> וארגון יכול לקבוע אילו תפקידים מותרים (או לכבות סוכנים) בקובץ מדיניות אחד.

| רכיב | מה |
|---|---|
| 🎙 בחלון | `VoiceButton` של D.Ai Voice ליד שורת המטרה: לחיצה מקליטה, לחיצה נוספת ממלאת את המטרה ומתחילה. מטרה שהגיעה בקול → התשובה נקראת בקול לבד (D.Ai Speak, `--stdin`). ‏`dai-agent window --speak` עושה זאת לכל ריצה (לנגישות, ל־TV) |
| טלפון | ה־deb של dai-agent כבר בתמונת הטלפון; החלון במצב מגע (`with_touch`), בדיקת הטלפון ב־VM דורשת `dai-agent window --version` ואת ה־desktop. אין קוד נפרד לטלפון |
| `agent.policy` (Tune) | היקף מערכת: "no agents" / "agents off" / "בלי סוכנים" → `DAI_AGENT_ROLES=none`; "agents: secretary, tutor only" / "סוכנים: רק secretary, tutor" → רשימה; "allow agents" / "אפשר סוכנים" → מוחק את הקובץ. נכתב ל־`/etc/dai/policy-agent.env` (0644). עובד גם מ־policy.d (מערכת) |
| אכיפה | `dai_agent/policy.py`: `allowed_roles()` קורא את הקובץ; ה־CLI, החלון (`main` ו־ComboBox שמציג רק תפקידים מותרים) ו־`agent.run` ב־Tune (validate) מסרבים לתפקיד שאינו מותר, עם שורה ברורה ("מדיניות ארגונית"). ‏Command: "agent:" לא מוצע כש־`none` |

בדיקות: יחידה (policy: קובץ חסר = הכול; none; רשימה; ה־CLI וה־validate מסרבים; החלון מראה רק תפקידים מותרים ו־Raz;
🎙 ממלא ומתחיל; `--speak` → dai-speak אחרי הסיום), ‏Tune (parser + `agent.policy`), ‏VM: בבדיקת הסוכן `dai-tune --yes
'agents: secretary only'` → `dai-agent run x --role guard` מסרב (קוד 2), `dai-tune undo` מחזיר; בבדיקת הטלפון
`AGENT_WINDOW=1`.

## 6ב. שלב 3: כלים נוספים, סוכנים מתוזמנים, זיכרון (נבנה 2026-11-01)

> אותו ארגז כלים סגור, אותם כללים. שלושה דברים: הסוכן מגיע לדואר (J), להסבר (Explain) ולהקלטה (Record); "כל יום
> ב־8 סוכן: …" הופך לטיימר של דרך היהלום שמריץ את הסוכן בלי שאלות **רק** בצעדים שלא מחלישים ולא דורשים מנהל;
> והסוכן זוכר בין ריצות רק מה שהאדם אישר לו לזכור.

### הכלים החדשים (tools.py)

| כלי | סיכון | מה |
|---|---|---|
| `mail(limit)` | קריאה | הדואר הנכנס האחרון מה־store המקומי של J (שולח, נושא, תאריך, ● לא נקרא; עד 10). בלי רשת, בלי גוף |
| `mail_summary(number)` | קריאה | סיכום ההודעה ה־N האחרונה (1 = החדשה) ב־Diamond, דרך אותה `summary_messages` של J (הגוף בגדר נתון, לא הוראה). הגוף נלקח מה־store רק אם J כבר הוריד אותו; אחרת: "פתחו אותה ב־J" |
| `explain(text)` | קריאה | D.Ai Explain על טקסט (שגיאה, הודעה): ההסבר + משפט Tune מוצע אם Diamond נתן אחד ו־Tune מבין אותו |
| `record(seconds)` | **פעולה** | D.Ai Record: הקלטת מסך שנעצרת לבד אחרי 5–600 שניות (`dai-record start N`); בלי קול, הקובץ ב־~/Videos/Recordings |
| `remember(text)` | **פעולה** | שורה לזיכרון הסוכן (`~/.local/share/dai/agents/memory.json`, 0600, עד 50 שורות של 200 תווים). נכנסת להנחיית המערכת של כל ריצה הבאה |

תפקידים: `secretary` מקבל `mail`, `mail_summary`, `remember`; ‏`tutor` מקבל `explain`; ‏`all` את הכול (גם `record`).

### סוכנים מתוזמנים (דרך היהלום)

| רכיב | מה |
|---|---|
| Tune parser | `agent[ ROLE]: GOAL` / `סוכן[ ROLE]: GOAL` → `Request("agent.run", {"goal", "role"})`; נבדק לפני פיצול הפסוקיות (המטרה היא טקסט אחד) |
| `agent.run` (catalog) | היקף משתמש, ניטרלי, בלי קבצים: `apply` מריץ `dai-agent run GOAL --role ROLE --yes --notify --lang LANG` (הסביבה הקבועה של Tune בלי LANG, לכן השפה עוברת כארגומנט) עם stdin סגור ו־timeout של 15 דקות; קוד היציאה של הסוכן לא מפיל את התוכנית (הריצה ביומן הסוכן ובהודעה), רק dai-agent חסר או timeout |
| `--notify` | בסוף הריצה: הודעה על המסך עם התשובה (או "נעצר"/"לא תכנן") — כך טיימר שאין לו טרמינל מדבר |
| `--yes` מתוקן | מאשר `do` רק כשתוכנית Tune של המשפט תקינה, לא מחלישה ולא דורשת מנהל (עד עכשיו `--yes` עדיין שאל על כל `do`; `plans.py` מחשב את זה גם לחלון) |
| טיימר | "every day at 8 agent secretary: summarize my mail" → `way.when` (קיים) → `dai-way run-when` → `apply_plan` → `agent.run`. ‏`dai-way when` מראה אותו; `dai-way when remove` מסיר |

### זיכרון בין ריצות (memory.py)

`load(home)`, `add(home, text)`, `forget(home, number)`, `clear(home)`. הזיכרון מצורף להנחיית המערכת ("What the person asked
you to remember:"). ‏CLI: `dai-agent memory`, `dai-agent memory forget N`, `dai-agent memory clear`. רק הכלי `remember`
(אישור!) כותב; המודל לא יכול לכתוב זיכרון בדרך אחרת. בחלון, כרטיס האישור של `remember` ו־`record` מראה במילים מה יקרה.

### פרטיות

`mail`/`mail_summary` מביאים שולחים ונושאים (וגוף אחד) אל Diamond; עם ספק חיצוני ל־general הם יוצאים אליו (השורה
הקבועה בחלון וב־CLI אומרת זאת). הזיכרון נשאר בקובץ 0600 ונמחק בשורה אחת. סוכן מתוזמן רץ בלי אדם: לכן `do` בו רק
לצעדים ניטרליים/מחזקים בהיקף משתמש, ולעולם לא החלשה או מערכת.

### בדיקות

יחידה: הכלים (J store זמני עם שתי הודעות; סיכום עם צ'אט מזויף; explain עם צ'אט מזויף; record דרך run מזויף; remember →
0600 + בהנחיה + forget/clear), ‏`--yes` מאשר `do` ניטרלי ודוחה מחליש, ‏`--notify`, ‏CLI memory, חלון (Raz עם כרטיס
record/remember). ‏Tune: parser (`agent: …`, `סוכן secretary: …`, לא פסוקיות), `agent.run` validate/summary/apply (ריצה
מזויפת), `way_sentence_requests("agent: …")` מתקבל, "every day at 8 agent: …" → `way.when`. ‏VM: בבדיקת הסוכן: script עם
`remember` + `mail` (בלי חשבונות → תשובה ברורה), `dai-agent memory` מראה שורה אחת, `dai-tune --dry-run "every day at 8
agent secretary: summarize my mail"` מציג תוכנית, `dai-tune --yes "agent tutor: …"` מסתיים ב־0.
