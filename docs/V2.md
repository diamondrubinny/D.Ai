# D.Ai v0.2: a more beautiful design and features no one else has (plan)

> Written on 2026-10-19 after "continue, make the design more beautiful, and add features that don't exist". Every stage: code, unit tests, Raz's accessibility check, a check on the VM and a screenshot in CI.
> Order by value to the user and by risk. ⏳ = next · 🔧 = in progress · ✅ = passes CI

## 1. Design

| # | What | Why | Size |
|---|------|-----|------|
| D1 🔧 | **One design system for every app: `dai_style`** | Today every app copies its own QSS (10 copies), and they are not always identical. One place for colors, corners, spacing and fonts, from which the QSS of every window is built | Medium |
| D1b 🔧 | **A light theme, "D.Ai Day", and a high-contrast theme** | Many people prefer light during the day. The theme follows the system choice (`dai-tune "light theme"` / "dark theme"). Raz checks AA contrast **in all three themes** in CI | Medium |
| D2 ✅ | **The way to the desktop:** a designed boot menu (GRUB theme), a loading screen with the diamond (Plymouth), and a login screen (SDDM) | Today the first 30 seconds look like a plain Linux system: text and gray. The first impression is the brand | Medium |
| D3 | **Wallpapers:** a set of 4 (night, day, gradient, minimal), plus one that changes with the time of day | | Small |
| D4 | **Uniform D.Ai app icons** (SVG, the same language as the diamond) | Today some apps have a generic icon | Small |

**Design rules (stay as they are):** contrast of at least 4.5:1 for text, visible focus, RTL, animations that stop when "reduce motion" is on, and no heavy blur (old computers).

### What was built (D1, D1b)

- **`dai_style`** (`apps/dai-i18n/dai_style`): three palettes (night, day, contrast) with the same 19 roles. `color(role)`, `rgba(role, alpha)`, and `themed(text)`, which turns a stylesheet written in Night colors into the person's theme.
- **Every D.Ai window takes the theme:** Command, Forge, Welcome, Heal, OEM, Clip, Privacy, Quick, J and MOM. Sheets built from tokens use `color()`. Sheets written as literal Night colors are passed through `themed()` once, where they are written; the two are never mixed, so nothing is mapped twice.
- **The choice:** `~/.config/dai/theme`, or `DAI_THEME` for one app. D.Ai Tune understands "light theme", "dark mode" and "high contrast" in Hebrew, English and the six other languages (`appearance.theme`, with undo).
- **Raz checks AA contrast in all three themes** for every window (`assert_accessible`). What it found and what was fixed:
  - D.Ai Quick's background was never painted (a translucent window does not paint its own QSS). It now sits on a card, as Command and Clip do.
  - Colors outside the palette (J, MOM) moved into it.
  - The day accent was darkened slightly for badges.
- **Still open:** the panel (LXQt), labwc and Firefox themes do not follow the choice yet.

- The USB boot menu is live-build's default: the Debian helmet and gray text.
- Plymouth is not installed, so kernel messages show during boot.
- SDDM has no theme. The installed system shows SDDM's built-in login screen.

**What was built, and it passes CI (90fc825; user, dev and edu):**
- `0450-dai-boot-look` (binary hook) for both USB menus, with "Start D.Ai OS" instead of "Live system".
- The `dai` Plymouth theme, plus `0250-dai-boot-look` (chroot hook), which makes it the default in the initrd.
- `50-dai.cfg` for the installed system's GRUB.
- The `dai` SDDM theme.
- Checks: unit tests (`tests/boot/test_boot_look.py`) and two VM checks. Screenshots: `login.png` and `boot-splash-{1,2,3}.png`.
- The login screen was checked locally in Qt 6.8.2 (the same version as Debian 13), with the translations from SDDM itself: English, Hebrew (RTL, Caps Lock warning) and Arabic.

**Images** are generated by a script (`build/scripts/make-boot-art.py`, PyQt6, from the diamond's SVG), and the PNGs are committed, so the image build needs no new tools.

**Risks:**
- Plymouth hides boot messages. "Escape" shows them. The CI checks boot the kernel without `splash`, so serial-console diagnostics stay as they are.
- A real computer with Secure Boot: GRUB with a theme is the same signed GRUB, so nothing changes. **This requires checking on real hardware.**

## 2. Features that don't exist (or not like this)

| F1 🔧 | **Copy text from the screen (OCR), Super+Shift+T** | Mark an area: the text (Hebrew and English) goes to the clipboard. From there, "translate" or "explain" with Diamond | Tesseract locally, nothing is saved | Small |
| F2 ✅ | **Focus mode** ("focus for 25 minutes", a button in Quick) | Built as **D.Ai Focus** (`docs/BEYOND.md` §5): do not disturb + a warmer light + a user timer, everything put back at the end; no "what was missed" summary (the notification daemon keeps none that can be read safely) and not through Tune: a session is not a setting | Local | Small |

### F1: what was built (waiting for CI)

- **`dai-ocr`** (`apps/dai-ocr`):
  - Super+Shift+T, then choose an area with the mouse (`slurp`). Its picture is taken into memory only (`grim` to stdout).
  - Tesseract reads it in the interface language plus English: `heb+eng` in Hebrew, `ara+eng` in Arabic, and so on.
  - The text goes to the clipboard, with a notification: "Text copied (N characters)" and the beginning of the text.
  - Esc does nothing. When there is no text, the notification says so and suggests a larger area.
- **Also from files:** `dai-ocr --file picture.png`; `--print` prints instead of copying.
- **In D.Ai Command:** "copy text from the screen", "text from this picture", "העתקת טקסט מהמסך", "זיהוי טקסט".
  - "read the text file" stays with D.Ai Find.
- **In the shortcut list** (Welcome, DESIGN.md) and in the app menu: "Copy text from the screen".
- **Packages:**
  - `tesseract-ocr` with the data for D.Ai's eight languages, about 20 MB in all;
  - `osd` comes in as a dependency of the engine.
- **Privacy:** nothing is saved. The picture is not written to disk, and the text goes only to the clipboard. D.Ai Clip still filters out passwords, as with any copy.
- **Checks:**
  - Unit tests (`apps/dai-ocr/tests`), with the screen and the engine replaced by fakes.
  - VM (`ocr: text from a picture`): Qt draws "Hello from 2026" and "שלום עולם", and `dai-ocr` reads them back.
